🚀 QUICK START
═══════════════════════════════════════════════════════════════════════════

Terminal 1 - Start Sync API:
  $ cd sync/api
  $ npm install  (first time only)
  $ npm run dev
  → Open: http://localhost:3002/swagger

Terminal 2 - Start Client API:
  $ cd client/api
  $ npm run worker:dev
  → Open: http://localhost:8787/swagger

🔧 ADDING NEW ENDPOINTS

Sync API (JSDoc-based):

   * @swagger
   * /api/local/example:
   *   get:
   *     summary: Get example data
   *     tags: [Example]
   *     responses:
   *       200:
   *         description: Success

    res.json({ data: 'example' });
  });

Client API (OpenAPI spec):
  Edit the '/swagger' endpoint in client/api/worker/index.ts:
  '/api/example': {
    get: {
      summary: 'Get example data',
      tags: ['Example'],
      responses: { 200: { description: 'Success' } },
    },
  }

🐛 TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════

Swagger UI not loading?
  → Check that the server is running on the correct port
  → Check browser console for errors
  → Try refreshing the page

Endpoints not showing?
  → For Sync API: Check JSDoc comment formatting
  → For Client API: Verify endpoint is in OpenAPI spec
  → Refresh the Swagger UI page

CORS errors?
  → Both APIs have CORS enabled for local development
  → Check FRONTEND_URL environment variable

Port already in use?
  → Kill the process on that port
  → Or use a different port in environment variables
